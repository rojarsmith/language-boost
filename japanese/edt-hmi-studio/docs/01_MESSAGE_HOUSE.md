# EDT HMI Studio 訊息屋

用途：讓 30 秒、2 分鐘、5 分鐘、Demo 與高階問答都講同一件事。先記「屋頂一句話」，再依對方身分選兩根支柱，不要把所有功能一次倒完。

## 1. 屋頂：唯一核心訊息

中文思路：

EDT HMI Studio 把嵌入式 HMI 從畫面到硬體的工作連成一個可追蹤的專案流程，讓團隊更早看見整合問題，並在對應硬體與標準功能範圍內減少手寫應用程式碼。

對外日文：

「EDT HMI Studioは、画面設計、ロジック、機器通信、検証、対応ハードウェアへの展開を、一つのプロジェクトでつなぐ組み込みHMI開発環境です。」

かな：

「イー・ディー・ティー エイチ・エム・アイ スタジオ は、がめん せっけい、ロジック、きき つうしん、けんしょう、たいおう ハードウェア への てんかい を、ひとつ の プロジェクト で つなぐ くみこみ エイチ・エム・アイ かいはつ かんきょう です。」

接續句：

「対応ボードと標準機能の範囲では、アプリケーションコードを手で書かずに開発できます。」

かな：

「たいおう ボード と ひょうじゅん きのう の はんい では、アプリケーション コード を て で かかず に かいはつ できます。」

## 2. 四根支柱

### 支柱一：一個專案，串起原本分散的工作

客戶價值：

- 畫面、logic、tag、protocol 與 board profile 放在同一份專案資料中。
- 設計變更較容易追蹤，不必在多個工具之間反覆重建相同資訊。
- 可重用 container、文字資源與 typography 有助於維持產品線一致性。

可見證據：

- EVK Coffee Bar 同一專案含 5 個畫面、3 種語言、23 個 tags、1 個 logic graph 與 1 組 Modbus link/device。
- Code Preview 會呈現同一專案產生的 ui、event、logic C 檔。

對外日文：

「画面、ロジック、タグ、通信設定を同じプロジェクトで管理するため、変更の影響を追いやすくなります。」

かな：

「がめん、ロジック、タグ、つうしん せってい を おなじ プロジェクト で かんり する ため、へんこう の えいきょう を おいやすく なります。」

不可偷加的承諾：不要說一定縮短多少工時、一定降低多少成本。沒有核准的量測數據時，用「しやすくなります」而非百分比。

### 支柱二：由快速構想到產生碼驗證，逐層提高信心

客戶價值：

- Prototype 適合快速確認版面與流程。
- Simulator 適合看真實 LVGL 的預建渲染。
- Emulator 會把當次產生的 C 與真實 LVGL 編譯，執行 event、logic 與模擬 Modbus。
- Deploy 才是在實際板卡上驗證記憶體、時序、面板、觸控與實體通訊。

可見證據：

- 四層 preview ladder 在產品文件中有明確的能力與限制。
- firmware 與 Emulator 的主要 LVGL 目標為 9.5.0；預建 Simulator artifact 仍是 9.2，不能混稱同一條證據。

對外日文：

「早い段階ではすぐに画面を確認し、その後は生成したCコードを実際のLVGLと一緒にコンパイルして、実機へ進む前に動作を確認できます。」

かな：

「はやい だんかい では すぐ に がめん を かくにん し、その ご は せいせい した シー コード を じっさい の エル・ブイ・ジー・エル と いっしょ に コンパイル して、じっき へ すすむ まえ に どうさ を かくにん できます。」

必要的限制句：

「最終的なメモリ、タイミング、表示、通信品質は、対象の実機で確認します。」

かな：

「さいしゅうてき な メモリ、タイミング、ひょうじ、つうしん ひんしつ は、たいしょう の じっき で かくにん します。」

### 支柱三：不是只有畫面，而是理解板卡與裝置通訊

客戶價值：

- Board profile 限制解析度、方向、pixel format、記憶體與可用 connector，降低把錯誤設定帶到硬體階段的風險。
- Modbus RTU 與 configurable serial commands 可把 tags、UI 與 host/controller 的資料交換連起來。
- Panel asks 與 panel answers 能對應不同系統分工。
- Host interface 可匯出 CSV、header 與 HTML，便於雙方確認介面。

可見證據：

- 目前追蹤版有 F746、H747、EVK043027B 三個 board profiles。
- H747 文件有 Modbus responder/client 與 serial responder 的實機 COM 測試記錄。
- CAN 只有連接層與 loopback 證據，尚不能拿來證明 tag/widget 資料路徑。

對外日文：

「ボードごとの表示、メモリ、接続条件をプロファイルで管理します。主要なシリアル経路では、Modbus RTUと設定可能なコマンド方式を利用できます。」

かな：

「ボード ごと の ひょうじ、メモリ、せつぞく じょうけん を プロファイル で かんり します。しゅよう な シリアル けいろ では、モドバス アール・ティー・ユー と せってい かのう な コマンド ほうしき を りよう できます。」

不可偷加的承諾：不要把「有 connector」說成「protocol 已可量產」；CAN、RS485、USB HS、Ethernet 都要逐項講實際 stack 與板卡狀態。

### 支柱四：AI 是受控的加速器，不是自主交付者

客戶價值：

- AI 使用與正常 editor 相同的受驗證資料操作，不直接繞過專案模型。
- 結果可以單次復原。
- OpenRouter key 留在本機 bridge，不寫入頁面、專案或 log。
- 可選 OpenRouter 或 Ollama；資料送到哪裡取決於 provider 與設定的 host。
- AI 是 optional；不使用 AI 也不妨礙主要設計、通訊與部署流程。

可見證據：

- 目前有 17 個工具，範圍不含 Deploy、port、Preferences、整個專案或資源刪除。
- OpenRouter 與 Ollama 的 provider 路徑已有驗證，但尚無已發布的整體品質 benchmark，packaged desktop leg 也仍待完成。
- Ollama 的 vision＋tools gate 只證明 capability；本機小模型實測曾誤解簡單需求。

對外日文：

「AIは任意の支援機能です。検証された編集経路を使い、結果を取り消せるようにしています。最終判断はエンジニアが行います。」

かな：

「エーアイ は にんい の しえん きのう です。けんしょう された へんしゅう けいろ を つかい、けっか を とりけせる よう に して います。さいしゅう はんだん は エンジニア が おこないます。」

不可偷加的承諾：不要說 AI 能一次生成所有產品、品質已達 production、懂所有板卡，或可以自動 Deploy。

## 3. 地基：三項可信度原則

### 原則一：限定範圍

每次說「支援」時都補齊四個條件：哪個版本、哪個 board、哪個 connector／protocol、在哪種測試環境。

「今回ご説明する範囲は、現在の開発スナップショットと対応ボードです。」

かな：

「こんかい ごせつめい する はんい は、げんざい の かいはつ スナップショット と たいおう ボード です。」

### 原則二：展示與證據一致

Demo 畫面只能證明實際展示到的東西。EVK Coffee Bar 沒有 media payload，所以不能用它證明 Video；Shizuku 雖已完成兩板 firmware build，但尚未燒錄到實體板；Emulator 畫面也不能證明實機效能。

「ここで確認できる内容と、実機で確認すべき内容を分けてご説明します。」

かな：

「ここ で かくにん できる ないよう と、じっき で かくにん すべき ないよう を わけて ごせつめい します。」

### 原則三：未知不猜測

「条件を確認してから、正確な回答をお送りします。」

かな：

「じょうけん を かくにん して から、せいかく な かいとう を おおくり します。」

## 4. 依聽眾選擇訊息

### 總經理／社長

先講：一個專案串流程、產品線一致性、提早發現整合風險。不要先報 25 個 widgets。

「複数の工程を一つのプロジェクトでつなぎ、製品ライン全体で設計情報を再利用しやすくします。」

かな：

「ふくすう の こうてい を ひとつ の プロジェクト で つなぎ、せいひん ライン ぜんたい で せっけい じょうほう を さいりよう しやすく します。」

接著問：量產時最常卡在 UI 變更、控制器介面，還是硬體驗證？

### 副總／事業負責人

先講：workflow、跨團隊交接、可重用資產與 host interface。若談商務，明確說價格與提供條件要由正式窗口確認。

「御社の開発フローに合わせて、どこから評価を始めるのが効果的か、一緒に整理したいと考えています。」

かな：

「おんしゃ の かいはつ フロー に あわせて、どこ から ひょうか を はじめる の が こうかてき か、いっしょ に せいり したい と かんがえて います。」

### 通路商／區域總經理

先講：適合哪類客戶、Demo 可重複性、qualification 問題、總部可提供的技術證據。不要先承諾區域獨家、折扣或上市日。

「まず、対象市場で多いボード、通信方式、量産条件を確認し、評価シナリオを標準化したいと思います。」

かな：

「まず、たいしょう しじょう で おおい ボード、つうしん ほうしき、りょうさん じょうけん を かくにん し、ひょうか シナリオ を ひょうじゅんか したい と おもいます。」

### 技術經理／架構師

先講：generator、LVGL version、preview ladder、protocol role、board constraint、flash guard。主動說限制，可信度反而更高。

「技術的な評価では、生成コード、LVGLの版、メモリ、通信の役割、書き込み条件を分けて確認できます。」

かな：

「ぎじゅつてき な ひょうか では、せいせい コード、エル・ブイ・ジー・エル の はん、メモリ、つうしん の やくわり、かきこみ じょうけん を わけて かくにん できます。」

## 5. 三段式說服順序

1. 先說客戶問題：HMI 資訊散落在 UI、韌體、protocol 文件與硬體設定。
2. 再說 EDT 方法：同一專案串 Design、Logic、Protocol、Preview、Deploy。
3. 最後給證據：Coffee Bar、產生 C、Emulator、board profile、已驗證的 serial 路徑。

問題句：

「現在、画面変更から実機確認までの間で、最も時間がかかる工程はどこでしょうか。」

かな：

「げんざい、がめん へんこう から じっき かくにん まで の あいだ で、もっとも じかん が かかる こうてい は どこ でしょう か。」

承接句：

「その工程を、同じプロジェクトの中でどこまでつなげられるかをご覧ください。」

かな：

「その こうてい を、おなじ プロジェクト の なか で どこ まで つなげられる か を ごらん ください。」

## 6. 高階主管常問的五個問題

### 「一般的なGUIビルダーと何が違いますか。」

「画面だけでなく、ロジック、タグ、機器通信、生成コード、対応ボードへの展開までを同じプロジェクトで扱う点です。」

かな：

「がめん だけ で なく、ロジック、タグ、きき つうしん、せいせい コード、たいおう ボード への てんかい まで を おなじ プロジェクト で あつかう てん です。」

### 「本当にコードは不要ですか。」

「対応ボードと標準機能の範囲では、アプリケーションコードを手で書かずに進められます。新しいボードや特殊な動作には、追加の実装が必要な場合があります。」

かな：

「たいおう ボード と ひょうじゅん きのう の はんい では、アプリケーション コード を て で かかず に すすめられます。あたらしい ボード や とくしゅ な どうさ には、ついか の じっそう が ひつよう な ばあい が あります。」

### 「当社のボードに対応できますか。」

「まず、MCU、表示方式、解像度、メモリ、通信インターフェースを確認します。現在の三つのプロファイルとの差分を整理して回答します。」

かな：

「まず、エム・シー・ユー、ひょうじ ほうしき、かいぞうど、メモリ、つうしん インターフェース を かくにん します。げんざい の みっつ の プロファイル と の さぶん を せいり して かいとう します。」

### 「AIで全部自動化できますか。」

「AIは設計を支援する任意機能です。現在は受け付ける操作を制限し、取り消しと人による確認を前提にしています。」

かな：

「エーアイ は せっけい を しえん する にんい きのう です。げんざい は うけつける そうさ を せいげん し、とりけし と ひと に よる かくにん を ぜんてい に して います。」

### 「いつ、いくらで提供しますか。」

「提供時期、価格、条件は現在最終調整中です。案件条件を確認し、正式な窓口から回答します。」

かな：

「ていきょう じき、かかく、じょうけん は げんざい さいしゅう ちょうせいちゅう です。あんけん じょうけん を かくにん し、せいしき な まどぐち から かいとう します。」

## 7. 對話用的三個探索問題

一次只問一題，聽完再追問。

「現在お使いのMCUと表示方式を教えていただけますか。」

かな：

「げんざい おつかい の エム・シー・ユー と ひょうじ ほうしき を おしえて いただけます か。」

「パネル側がデータを取りに行きますか。それとも、ホストからの要求に応答しますか。」

かな：

「パネル がわ が データ を とり に いきます か。それとも、ホスト から の ようきゅう に おうとう します か。」

「評価で最初に確認したいのは、画面品質、通信、生成コード、実機性能のどれでしょうか。」

かな：

「ひょうか で さいしょ に かくにん したい の は、がめん ひんしつ、つうしん、せいせい コード、じっき せいのう の どれ でしょう か。」

## 8. 收束與下一步

「御社の対象ボードと通信条件を一つ選び、小さな評価プロジェクトで確認するのが、次の一歩として現実的です。」

かな：

「おんしゃ の たいしょう ボード と つうしん じょうけん を ひとつ えらび、ちいさな ひょうか プロジェクト で かくにん する の が、つぎ の いっぽ と して げんじつてき です。」

結尾提問：

「今日ご覧いただいた中で、御社の課題に最も近い部分はどこでしたか。」

かな：

「きょう ごらん いただいた なか で、おんしゃ の かだい に もっとも ちかい ぶぶん は どこ でした か。」

## 9. 背誦優先順序

初學者不要整份硬背。依序練到能不看稿說出：

1. 屋頂一句話。
2. 支柱一與支柱二各一句。
3. 「實機仍需驗證」限制句。
4. 三個探索問題。
5. 不知道答案時的「確認後正式回覆」。
6. 最後才依聽眾加入 protocol、board 或 AI 細節。
