# Shizuku 洗衣機：日本客戶 10–12 分鐘追加 Demo 腳本

用途：接在公司／產品簡報之後，以「しずく（Shizuku）」洗衣機範例證明 EDT HMI Studio 能把日文 UI、資料、邏輯、Modbus 與板卡差異放進同一個專案流程。這是一條**選配 Demo**，不是取代 [主 Demo 腳本](07_LIVE_DEMO_SCRIPT.md)。

> 本稿依 `edt-hmi-studio` 追蹤版 HEAD `a7cc2a8`（2026-09-03）編寫。只使用追蹤檔 `examples/f746-washing-machine.json` 與 `examples/evk043027b-washing-machine.json`。  
> 上台的成功標準不是「八個畫面全部點完」，而是讓客戶記住：**一個日本市場情境、兩個板卡版本、四十三個 Modbus tags、清楚分級的驗證證據**。

## 1. 先學會怎麼用這份稿

- `操作`：你手上要做的事，不用念。
- `證據`：畫面或程式碼必須真的看得到；看不到就不說。
- `日文（口說）`：上台只念這些句子。
- `かな（照念）`：每一個口說句的完整讀法。`/` 是短停頓，`//` 是一句結束。
- 每一段最多記兩句。忘詞時，先停、指畫面，再念下一句，不要硬補日文。

最重要的誠實界線：

1. 這是 EDT 的日本市場提案用 reference design，不是 Sharp 已採用或已量產的產品。
2. 兩份專案都曾經由產品自己的 Deploy 路徑產生、編譯並連結成韌體。
3. 洗衣機專案的 runtime 證據只有 **F746 Emulator**；已看到的畫面是 待機、ホーム、完了。
4. 兩個版本都**尚未燒錄到實體板**；觸控玻璃、實際 FPS、SDRAM framebuffer、背光與真實 Modbus bus 品質都仍須實機驗證。

## 2. 上台提示卡：精確事實

| Text resources | 102 | 102 |
| Languages | 3：ja、en、zh-TW | 3：ja、en、zh-TW |
| Tags | 43 | 43 |
| Logic graphs | 17 | 17 |
| Serial connector | ST-LINK VCP | USB-C VCP |
| Protocol／角色 | 1 個 Modbus RTU device；panel asks | 1 個 Modbus RTU device；panel asks |
| Serial 設定 | 115200、8 data bits、no parity、1 stop bit、Unit ID 1 | 同左；另有 CRLF、5 ms gap 設定 |

共同基線：兩份檔案有相同的八個 screen identity、102 筆三語文字、43 個 tags 與 typography 定義；元件、動畫、connection 與 logic JSON 不是逐位元組相同，因為板卡版型會做成本調整。不要說「兩份專案所有內容完全相同」。

### 2.2 建置紀錄

| Board | text | data | bss | 文件記錄的 internal flash 占比 |
|---|---:|---:|---:|---:|
| F746 | 831,776 B | 840 B | 4,216,940 B | 約 79%／1 MB |
| EVK043027B | 853,888 B | 1,172 B | 1,181,428 B | 約 41%／2 MB |

每次建置包含 14 個 subset font files：Noto Sans JP 與 Noto Sans TC 的 16、18、20、22、24、32、48 px。這些是建置紀錄，不是實機 RAM／FPS 量測。

### 2.3 可指給工程師看的六個 tags

| Tag | Modbus 位置 | 用途 |
|---|---|---|
| `Phase` | input register 0 | 階段與畫面 routing；8 代表完成 |
| `RemainMin` | input register 1 | 剩餘分鐘 |
| `WaterLevel` | input register 6 | 滾筒水位計算 |
| `ErrorCode` | input register 11 | fault sheet routing |
| `CourseId` | holding register 0 | 面板選定行程 |
| `Start` | coil 0 | 啟動命令 |
